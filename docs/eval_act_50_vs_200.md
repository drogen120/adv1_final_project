# ACT：50 回合与 200 回合示教数据的对比

## 1. 实验设置

两个模型的设置完全相同，只有训练数据量不同：

| | act_50 | act_200 |
|---|---|---|
| 训练数据 | 前 50 回合（seed 0），25 300 帧 | 全部 200 回合（seed 0 + seed 1），101 200 帧 |
| 训练步数 / batch | 60k / 64 | 60k / 64 |
| 约等于 epoch 数 | **≈152** | ≈38 |
| 评估 checkpoint | `outputs/act_50/checkpoints/060000` | `outputs/act_200/checkpoints/060000` |

- 观测：关节角（6 维）+ 方块特征 `[x, y, z, cos 4yaw, sin 4yaw]`（5 维），无图像。`chunk_size = n_action_steps = 50`，不使用时间集成。
- 评估：`policy_eval`，`sim_node` 同步模式，**seed 100**，50 回合，每回合 600 帧（12 s）。
- 两次评估的方块初始位姿逐回合完全一致（已核对），所以可以**逐回合配对比较**。
- 数据：`data/eval/act_50_60k/`、`data/eval/act_200_60k/`。

## 2. 总体结果

| 指标 | act_50 | act_200 |
|---|---|---|
| 成功率 | **30/50 = 60%**（95% CI 46%–72%） | **48/50 = 96%**（95% CI 87%–99%） |
| 方块被抬起 | 30/50 | 48/50 |
| 失败类型 | 20 次都是“没抓起来” | 2 次都是“没抓起来” |
| 成功回合的放置误差（平均 / 中位数 / 最大） | 0.69 / 0.66 / 1.46 cm | 0.70 / 0.55 / 1.58 cm |
| 推理耗时 | 约 1.6 ms/步 | 约 2.0 ms/步 |

逐回合配对：

| | act_200 成功 | act_200 失败 |
|---|---|---|
| **act_50 成功** | 30 | 0 |
| **act_50 失败** | 18 | 2 |

- 18 个不一致的回合全部是 act_200 成功、act_50 失败，反过来的情况一次都没有。精确 McNemar 检验 p ≈ 7.6×10⁻⁶，差异是显著的，不是随机波动。
- act_200 的两次失败（36、37）act_50 也失败了：这是两个模型共同的困难区域。
- 两个模型的差别**只在抓取这一步**：一旦抓起来，搬运和放置的精度几乎一样（都在 0.7 cm 左右）。推理耗时的差别来自运行时负载，模型结构相同，可以忽略。

## 3. 失败机制：两个模型完全相同

`docs/eval_act_200_failure_analysis.md` 中对 act_200 的分析结论是：专家抓取时固定爪离方块侧面只有约 0.6 mm，策略在开合方向上的误差一旦让夹爪偏向方块，固定爪就会压到方块顶面边缘。act_50 的 20 次失败是同一种机制：

1. **都是固定爪先碰到方块。** 逐帧查接触（第 100–200 帧），所有失败回合（act_50 20 次，act_200 2 次）最先碰到方块的都是 `gripper` 刚体（固定爪所在的刚体）。成功回合大多是活动爪先碰到方块（act_200 41/48，act_50 12/30），也就是正常的夹取。
2. **都是被挡住而不是不往下走。** 失败回合闭合时，夹爪的指令高度在 z≈1.6 cm，实际高度停在 z≈4.1–4.8 cm（方块顶面在 4.0 cm）。
3. **用一个量就能完全区分成败。** 取下降途中、还没碰到方块的第 105 帧，计算 `gripperframe` 相对方块中心沿开合方向（`gripperframe` 的 z 轴，由固定爪指向活动爪）的偏差。两个模型合起来共 100 个回合：

| 开合方向偏差（cm） | act_200 成功 | act_50 成功 | 合计成功率 |
|---|---|---|---|
| < −1.00 | 8/8 | 2/2 | 100% |
| −1.00 ~ −0.50 | 17/17 | 4/4 | 100% |
| −0.50 ~ −0.25 | 7/7 | 2/2 | 100% |
| −0.25 ~ 0.00 | 10/10 | 8/8 | 100% |
| 0.00 ~ +0.25 | 6/6 | 14/14 | 100% |
| **+0.25 ~ +0.50** | 0/2 | 0/8 | **0%** |
| **+0.50 ~ +1.00** | – | 0/8 | **0%** |
| **> +1.00** | – | 0/4 | **0%** |

偏差在 +0.25 cm 以下的回合全部成功，以上的全部失败，分界非常干净。这和专家留下的约 0.6 mm 间隙一致：再加上下降过程中的少量漂移，偏差超过约 2.5 mm 时，固定爪就落到了方块顶面上。

**所以 50 回合和 200 回合的差距，本质上是同一个误差量的分布不同：**

| 第 105 帧的开合方向偏差 | act_50 | act_200 |
|---|---|---|
| 平均（系统偏差） | **+0.21 cm**（偏向危险一侧） | **−0.51 cm**（偏向安全一侧） |
| 标准差 | 0.65 cm | 0.45 cm |
| 落在危险区（> +0.25 cm）的回合 | 20/50 | 2/50 |

act_50 的问题有两个：一是误差更大（标准差多约 45%），二是平均值落在了危险的一侧。act_200 的平均值碰巧偏向安全一侧（−0.5 cm），所以它的高成功率有一部分要归功于这个偏向，而不全是因为精度更高。在专家余量只有 0.6 mm 的设计下，这种偏向的方向基本是偶然的，这也说明**给专家的抓取点加余量才是根本的解决办法**（见失败分析文档第 4.1 节）。

## 4. act_50 的失败分布在哪里

### 4.1 和训练数据覆盖的关系

用 (x, y, 相对抓取角) 衡量评估回合的方块摆放离最近一条训练示教有多远（2 cm 和 10° 各算 1 个单位）：

- 评估摆放到训练集的最近距离：50 回合训练集中位数 0.93，200 回合训练集中位数 0.64。数据多了 4 倍，覆盖明显更密。
- act_50 按最近距离分成三档，成功率分别为 11/17、12/16、**7/17**：离训练数据越远越容易失败。
- 最近距离和开合方向偏差的相关系数为 0.46：离训练数据越远，偏差越大。

这说明覆盖不足是 act_50 失败的一个重要原因，但相关性不算强，即使离训练数据很近的回合也有失败（11/17）。

### 4.2 按位置和朝向分组

| 分组 | act_50 | act_200 |
|---|---|---|
| 半径 0.17–0.20 m（靠近底座） | **4/12** | 12/12 |
| 半径 0.20–0.22 m | 12/20 | 20/20 |
| 半径 0.22–0.25 m（远端） | 14/18 | 16/18 |
| 相对抓取角 < −15° | 15/22 | 22/22 |
| 相对抓取角 −15° ~ 15° | 9/14 | 14/14 |
| 相对抓取角 > 15° | 6/14 | 12/14 |

- act_50 在**靠近底座**的区域最差（4/12）。可能的原因是这里机械臂折叠得更厉害，离 r < 0.16 m 的自碰撞区也不远，示教轨迹的形状和其他区域差别较大，50 回合不够覆盖（未验证）。
- act_200 仅有的两次失败在远端（r ≈ 0.23–0.24 m）、相对抓取角 > 15°，是两个模型共同的薄弱区域。
- act_50 在所有朝向分组中的平均偏差都是正的（+0.08 ~ +0.32 cm），说明它的偏差是整体性的，不是某一种抓法特有的。

### 4.3 可能的过拟合

两个模型都训练了 60k 步，但 act_50 的数据只有 act_200 的四分之一，相当于约 152 个 epoch（act_200 约 38 个）。小数据集上训练这么久，可能已经过拟合，这也可能是系统偏差的来源之一。这一点还没有验证：目前只评估了 60k 的 checkpoint，需要用同一 seed 评估 act_50 的 10k–50k checkpoint 才能下结论。

## 5. 结论

1. **数据量从 50 增加到 200 回合，成功率从 60% 提升到 96%**，差异显著（配对比较 18:0，p ≈ 7.6×10⁻⁶）。
2. 提升**全部来自抓取阶段**：两个模型抓起来以后的放置精度相同。
3. 两个模型的**失败机制完全相同**：固定爪压在方块顶面边缘，用下降途中开合方向的偏差（阈值约 +0.25 cm）就能完全预测成败。数据量的作用是**减小这个偏差的离散程度**（0.65 → 0.45 cm），并让它的平均值落在了安全的一侧（+0.21 → −0.51 cm）。
4. act_50 的失败集中在离训练数据较远、以及靠近底座的摆放上，说明 50 回合对这个工作空间的覆盖不够。
5. 根本问题在于专家的抓取余量只有约 0.6 mm，这个设计放大了数据量的影响。给专家的抓取点加上 0.8–1.0 cm 的偏移后，两个模型的成功率都应该会提高，数据量带来的差距也可能缩小。这本身就是一个值得做的对比实验。

## 6. 后续实验建议

按优先级排列：

1. **评估 act_50 的其他 checkpoint**（10k–50k，seed 100），确认 60k 是否已经过拟合，并给出两种数据量下各自最好的 checkpoint 来对比，这样更公平。act_200 也同样做一遍。
2. **修改专家的抓取余量**后，重新采集数据并训练 50 / 200 回合两个模型，看余量对数据效率的影响（详见失败分析文档第 4.1 节）。
3. **执行方式**：用 `--temporal-ensemble 0.01` 或 `--n-action-steps 25` 重新评估两个模型，看能不能减小抓取偏差。
4. **增加评估回合数**到 100–200，缩小置信区间，特别是 act_200 这种接近 100% 的情况。
5. 可选：再补一个 100 回合的模型，画出“数据量—成功率”曲线。

## 附：复现方法

```bash
# 评估（终端 1 推理服务 + 终端 2 sim_node seed 100 + 终端 3 policy_eval，见 README）
ros2 run so101_mujoco policy_eval --ros-args -p num_episodes:=50 -p output_dir:=data/eval/act_50_60k

# 渲染失败回合与对照的成功回合
pixi run python scripts/render_eval_cases.py data/eval/act_50_60k
```

本文中的开合方向偏差、首次接触刚体、训练覆盖距离等指标，是用 MuJoCo 正运动学和接触检测从 `rollouts.npz` 离线计算的（在 `observation_state` 上做正运动学，方块位姿取自 `observation_environment_state`）。
