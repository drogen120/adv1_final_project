# 图像版 ACT（480 回合：完成后保持 + 边界补充数据）闭环评估

## 1. 实验设置

目的：针对 `docs/eval_act_images.md` 中的两个问题改了示教数据，用同样的观测重新训练，看是否改善：

1. 成功后手臂回到初始姿态，又会去方块原来的位置附近再抓一次（示教回合末尾只有 0.5 s 保持，比 1 s 的动作块短）；
2. 在换抓法的边界附近（|g| ≳ 35°）失败（第 4 节）。

| | 新模型 | 旧图像模型（对照） |
|---|---|---|
| 观测 | 关节角 + `overview` + `wrist_cam`（240×320 RGB），无方块坐标 | 同左 |
| 训练数据 | `data/lerobot/so101_sim_pick_place_images_all_hold`（480 回合，274,790 帧） | `so101_sim_pick_place_images_291`（291 回合，142,605 帧） |
| checkpoint | `outputs/act_img_all_hold/checkpoints/100000`（另评估了 060000） | `outputs/act_img_291/checkpoints/060000` |
| 训练 | ResNet18，batch 64，100k 步（约 23 个 epoch），四类特征 MEAN_STD | 同左，60k 步（约 27 个 epoch） |

新数据（`data/demos_all_hold.npz`）的组成，每回合末尾都有 2 s 停在初始姿态的保持帧（`collect_demos` 的 `settle_time` 从 0.5 s 改为 2.0 s）：

| 数据 | seed | 方块朝向 | 注入 | 成功回合 |
|---|---|---|---|---|
| `demos_offset_hold` | 2 | 默认 | — | 200 |
| `demos_retry_hold` | 3 | 默认 | `wrist` / `offset` | 94 |
| `demos_boundary` | 4 | `box_rel_yaw_range:=[30.0,60.0]`（\|g\| ∈ [30°, 45°]） | — | 100 |
| `demos_boundary_retry` | 5 | 同上 | `midway` | 86 |

- `midway` 注入模仿旧图像模型在边界处的失败：手腕转回到两种抓法的中间（偏差 = −g × 0.7–1.0，`wrist_roll` ≈ 1.6），同时朝活动爪平移 7–11 mm，第一次抓取故意失败，只导出重抓的部分。
- 抓空后，如果方块没有平放在某个面上（多数是被斜着卡在夹爪里），专家先张开夹爪、竖直抬高末端，让方块倒平，再重抓。
- 评估：与 `eval_act_images.md` 相同（`policy_eval`，同步模式，每回合 900 帧，`chunk_size = n_action_steps = 50`），用 `scripts/run_evals.sh` 运行，结果在 `data/eval/act_img_all_hold_*`。
- seed 101：新模型的第 k+1 回合对应旧图像模型的第 k 回合（旧图像模型那次评估多重置了一次）；新模型这次和状态模型的 `act_291_envnorm_retry_60k_100` 是对齐的。下面 seed 101 的配对比较按这个偏移对齐，共 99 对。

## 2. 总体结果

| 评估 | 旧图像模型 60k | 新模型 100k | 新模型 60k | 状态模型 |
|---|---|---|---|---|
| seed 100 普通（50） | 49 | **47**（失败 1、7、22） | 48（22、44） | 50 |
| seed 100 边界（50） | 47 | **50** | 47（1、37、49） | 50 |
| seed 101 普通（100） | 98 | **99**（80） | — | 100 |
| **合计** | **194/200** | **196/200** | | **200/200** |

- 配对比较（旧 60k 对新 100k）：

| 评估 | 只有旧模型成功 | 只有新模型成功 |
|---|---|---|
| seed 100 普通 | 2（ep 1、22） | 0 |
| seed 100 边界 | 0 | 3（ep 3、30、39） |
| seed 101 普通 | 1（新 ep 80） | 2（新 ep 9、49，即旧 ep 8、48） |
| 合计 | 3 | 5（McNemar p = 0.73） |

- 总体上不能说新模型更好；单看边界评估是 0 对 3（p = 0.25），方向一致，但还不显著。
- 100k 比 60k 好：60k 在边界评估上仍是 47/50，3 个失败都是固定爪先碰到方块、压在方块顶上（jaw 偏移 +0.27 到 +0.41 cm），和旧模型一样。
- 放置精度和旧模型相当：成功回合的放置误差，seed 100 平均 0.64 cm（旧 0.54），边界 0.69 cm（旧 0.63），seed 101 0.67 cm（旧 0.55）。

## 3. 成功后保持不动：已解决

`scripts/after_success.py`：在每个成功回合中，找 `success_frame` 之后手臂第一次回到初始姿态的帧（5 个关节都在第 0 帧的 0.05 rad 以内），统计从这一帧到回合结束（约 430 帧）关节的最大偏移；超过 0.2 rad 记为"又动了"。

| 评估 | 成功 | 又动了 | 最大偏移（中位数 / 最大） |
|---|---|---|---|
| 旧图像模型，seed 100 普通 | 49 | 49 | 1.39 / 1.45 rad |
| 旧图像模型，边界 | 47 | 46 | 1.39 / 1.43 rad |
| 旧图像模型，seed 101 | 98 | 97 | 1.39 / 1.45 rad |
| **新模型 100k，seed 100 普通** | 47 | **0** | 0.04 / 0.05 rad |
| **新模型 100k，边界** | 50 | **0** | 0.04 / 0.05 rad |
| **新模型 100k，seed 101** | 99 | **0** | 0.04 / 0.05 rad |
| 新模型 60k，seed 100 普通 / 边界 | 48 / 47 | 0 / 1 | |
| 状态模型，seed 100 / seed 101 | 50 / 100 | 0 / 0 | 0.04 / 0.05 rad |

- 旧图像模型回到初始姿态后，几乎每次都会再伸手出去（约 1.4 rad），只是没有碰到方块，所以不影响成功率。状态模型本来就不会，问题只出现在图像模型上：图像模型从方块的画面推断"该去抓了"，而训练数据里没有"方块在目标上、手臂在初始姿态"的画面。
- 把示教末尾的保持段加长到 2 s（比 1 s 的动作块长）后，这个现象完全消失了。

## 4. 抓取精度

`scripts/grasp_metrics.py` 计算，定义同 `eval_act_images.md` 第 3 节。

| 指标 | 旧图像模型 | 新模型 100k |
|---|---|---|
| **边界评估** | | |
| \|yaw err\| > 10° 的回合 | 19/50 | 14/50 |
| yaw err，g < 0 / g > 0 | −4.0 ± 19.7° / −5.0 ± 11.3° | +7.2 ± 16.0° / −1.5 ± 12.8° |
| 固定爪先碰到方块 | 21/50 | **2/50** |
| jaw 偏移（第 105 帧，专家 −0.90 cm） | −0.62 ± 0.51 cm | −0.98 ± 0.48 cm |
| 第 150 帧末端仍高于 5 cm | 0/50 | 8/50 |
| **seed 101** | | |
| \|yaw err\| > 10° 的回合 | 13/100 | 9/100 |
| 固定爪先碰到方块 | 18/100 | **1/100** |
| jaw 偏移 | −0.74 ± 0.40 cm | −1.01 ± 0.28 cm |
| yaw err，g ∈ [+15°, +35°) | +7.1 ± 4.0° | +3.4 ± 3.3° |
| 第 150 帧末端仍高于 5 cm | 0/100 | 8/100 |

- **朝向估计只是略有改善**：边界附近的误差仍有 ±13°–16°，"该选哪对侧面"这个问题本身没有解决。
- **改善主要来自抓取位置**：jaw 偏移回到专家的水平（约 −1.0 cm），固定爪离方块有足够余量。即使朝向偏了，固定爪也落在方块外侧，闭合时会把方块转正。旧模型的失败是"朝向偏 + 位置偏向活动爪"两者叠加，现在少了后一个。
- **新行为：拿不准时先停一下**。有 8 个边界回合在第 150 帧时末端还高于 5 cm（旧模型 0 个）：模型在方块上方停住，转好手腕再下去。例：边界 ep 4（g = −45.0°），第 120 帧朝向偏 35.6°，第 150 帧末端还在 8.4 cm，最后成功。这可能来自 `midway` 恢复数据，也可能来自边界示教数据量的增加，这次的实验分不开。
- 不在边界的区域，系统偏差变小了（g ∈ [+15°, +35°) 从 +7.1° 降到 +3.4°）。

## 5. 失败分析

### 5.1 新出现：搬运途中掉落（seed 100 ep 1、ep 22）

两个回合都已经把方块抬到约 5 cm，在去目标的半路上掉了，落在 (0.225, 0.01) 附近。旧模型这两个回合都成功了。

| 回合 | g | 过程 |
|---|---|---|
| ep 1 | +30.9° | 下降偏晚（第 150 帧末端 2.8 cm，专家 1.5 cm），固定爪先碰到方块，方块在夹爪里转了约 6°；抬起后，夹爪指令从第 265 帧起慢慢从 0 升到 0.29，第 310–325 帧方块掉下 |
| ep 22 | +43.8° | 在方块上方犹豫约 200 帧，手腕从 1.36 慢慢转到 0.74，最后换成另一对侧面去抓（第 385 帧左右闭合）；抬起后夹爪指令升到 0.1 左右，搬运途中掉下 |

两个共同点（方块中心在夹爪坐标系中的位置，取方块离地 3.5 cm 后第 5–15 帧的平均值，用 MuJoCo 正运动学离线计算）：

| 指标 | 成功回合（47） | ep 1 | ep 22 |
|---|---|---|---|
| 方块中心在夹爪宽度方向上的偏移 | 0.37 ± 0.26 cm（最大 1.02） | 1.46 cm | 2.11 cm |
| 搬运时（离目标较远）夹爪指令的最大值 | 47 回合都在 0.1 以下（中位数 0.00） | 0.29 | 约 0.1 |

- 也就是：只夹住了方块的边缘，同时夹爪在慢慢松开，方块就滑出去了。
- 松爪的原因还不确定。一个可能是新加的松爪恢复片段：训练数据里有 204 帧、来自 66 个回合，是在方块离地、离目标较远时张开夹爪的（方块被斜着卡在夹爪里）。但那些帧里方块高约 2.7 cm、夹爪状态约 0.22，和这两个回合（5 cm、0.32）不太一样；旧模型也有 3/49 个成功回合搬运时指令超过 0.1，并没有掉。只有 2 个样本，还不能下结论。

### 5.2 与旧模型相同：手腕停在中间（seed 100 ep 7）

g = +35.9°，`wrist_roll` = 1.60（正好是两种抓法的中点），朝向偏 35.4°，抓了 5 次都没抬起。旧模型在这个回合也失败了，原因相同（`eval_act_images.md` 第 4 节）。

### 5.3 g ≈ +26°：手腕转过头（seed 101 ep 80；60k 的 seed 100 ep 44）

| 回合 | g | `wrist_roll` | yaw err | 第 150 帧末端 z | 过程 |
|---|---|---|---|---|---|
| seed 101 ep 80（100k） | +26.0° | 2.25 | +14.6° | 4.3 cm | 固定爪先碰到方块，闭合两次都没夹住，方块没动 |
| seed 100 ep 44（60k） | +26.4° | 2.20 | +10.0° | 4.3 cm | 固定爪先碰到方块，没夹住 |

- 加上 ep 1（g = +30.9°），新模型的 3 个新失败都在 g ≈ 26°–31°，刚好在补采范围 [30°, 45°] 的外边。一个可能的解释是：边界数据让 g > 0 一侧的手腕角整体偏大。但 g ∈ [+15°, +35°) 的平均朝向误差反而变小了（第 4 节），样本也太少，先记下来，之后的评估里注意观察。

## 6. 结论

1. **完成后保持不动：已解决。** 示教末尾的保持段加长到 2 s 后，图像模型成功后再动的回合从 192/194 降到 0/196，和状态模型一致。
2. **边界区域：失败方式变了，但统计上还不显著。** 边界评估 47/50 → 50/50（配对 0 对 3，p = 0.25）。改善主要来自抓取位置回到专家水平（固定爪先碰到方块 21 → 2），以及拿不准时先停一下；朝向估计本身只略有改善。
3. **总体成功率与旧模型持平**：196/200 对 194/200（p = 0.73），仍不如状态模型（200/200）。
4. **新出现的失败**：抓的位置偏到方块边缘，同时夹爪在搬运时慢慢松开，方块中途掉落（2 回合）。原因待确认。
5. 100k 优于 60k，作为当前最好的图像模型。

## 7. 今后的对策

1. 交互演示的图像模型换成 `act_img_all_hold` 100k。
2. 确认搬运掉落是否稳定复现：用新的 seed（比如 102）再跑 100 回合普通评估，单独统计掉落次数。
3. 试 ACT 的时间集成（`temporal_ensemble_coeff`，只改推理参数）：把多次预测平均，可能减小搬运时夹爪指令的漂移，也可能让边界附近的手腕角更稳。
4. 如果掉落问题确认存在，考虑减少或调整松爪恢复片段（比如松爪前先降低高度，让画面和"正常搬运"区分得更开），再看掉落是否消失。专家搬运时的夹爪指令已经是完全闭合（0），这一侧没有调整空间。
5. 修改 `scripts/run_evals.sh`：seed 101 的配对改为和 `act_291_envnorm_retry_60k_100`（状态模型）比较，或者让 `grasp_metrics.py` 按方块初始位姿自动配对（`eval_act_images.md` 6.4 节也提过）。
